# AETHER 3.0 需求规格与验收矩阵

## 需求解读

用户提供的手写稿将**五项顶层功能**列为「基础数据」「想定管理」「联合投送方案」「行动推演」「评估分析」，并提及地图图层、环境条件、关键基础设施状态、力量编组、可视化部署、甘特图、时间轴、气象条件、平台类型和结果统计。个别字迹的语义基于工程分析做了合理解释。

本项目应用于 **民用城市应急物流无人运载平台的离线教学模拟**，不存在真实车辆远程控制与安全关键用途。

## 验收矩阵

## 重要限制

- 地图底图来自真实 OpenStreetMap，但业务设施为 **近似 WGS84 演示位置**；边为**人工定义的合成图结构**，不是实际道路网。地图与模拟路线必须以不同图例表达。
- 目前 A*、Dijkstra 和 Monte Carlo 的调度并非严格全局最优算法，不是已验证安全控制系统。
- 单机同步仿真约束在小型实验；跨实例队列、用户并发、生产地理数据和大型业务压测待实施。
- Chromium 沙箱若被环境策略阻断，语法与 HTTP 测试仍可执行，但不等于完成真实浏览器视觉验收。

### 验收边界

当前仿真展示的是民用城市物流教学用的合成事件，绝不连接真实作业车辆、真实设施控制、遥测设备或指挥通信系统。
运输与投送统计的逐任务结果取**随机推演第 1 次迭代**，累计成功率和准点率为**多轮均值**；两者不应当互相代替。
模拟位置只在路网地标之间插值，不能等同实时 GPS 或精确导航位置。浏览器被当前执行环境的管理员策略拦截，未获得图形化浏览器验收通过记录。
