# 全国跨区域陆海联运

默认范围为“全国跨区域物流”，原武汉、上海、成都、深圳场景仍可从范围选择器进入。`SCN-REGIONAL-CN` 独立使用 `regional` 路网，不改写城市场景、历史方案或推演。

## 示例规模

- 37 个设施和航路参考点，包含内陆枢纽、沿海港口、台湾基隆/台中/高雄接驳点及当地配送中心。
- 36 条陆运走廊、15 条海运走廊。
- 22 台干线货车、11 艘运输货船。
- 11 票民生物流运单、31 个运输分段，其中 9 段海运。
- 均衡、时效、稳健三类规划及各 80 轮仿真。

示例包括成都—厦门港—高雄港—高雄、武汉—福州港—基隆港—台北、南京—宁波港—台中港—台中，以及北京—郑州—武汉、昆明—贵阳—广州和盐田港—海口港。台湾也有台中港至厦门港的回运示例。

## 分段与接驳

每票运单有固定 `shipment_id`；分段包含 `leg_index`、`transport_mode`、`predecessor_task_id` 与 `handover_min`。海运只匹配船舶和海运通道，陆运使用陆运通道；不能用地面车辆跨越海面。

规划按依赖顺序分配运输，后段开始时间不早于前段计划结束加装卸时间，同时考虑承运平台的可用时间、驻地调位、载荷和航程。仿真进一步使用前段实际结束时间；前段延迟会传递至接驳，前段失败时取消后续运输，取消的分段不会产生虚构的行驶里程或送达位置。

API 创建接驳任务时校验同一想定、同一运单、连续分段序号、相同物资与重量及端点连续性。表单选择前序任务后会填入运单、序号、物资、重量和起点。单独修改某分段的物资/重量时，同一运单的其他分段同步修改；原有规划快照保持不变。有关联后段的任务不能直接删除。

## 地图、回放和统计

全国省界底图上显示跨省、跨市与跨海路网；海运路线为虚线，船舶和货车使用不同图标。“运单”面板逐段展示承运平台、接驳、执行和交付状态，支持查看整票运输路径。整票路径排除承运车辆在取货前的空驶调位，并隐藏其他运单的彩色路线。常规“全部任务路线”仍可查看全网。

底层时间统一使用分钟；运单面板同时给出小时值。长途回放默认 128×，可选 64×、256×、1024×等倍速，也可拖动时间轴或使用定位快捷点。

完成率和事件统计区分分段任务与整票运单。整票交付必须全部分段交付；运单准点率按末段交付时限判定。交付重量按运单去重，避免同一物资陆运、海运、末端配送被重复计入总量。CSV 包含运单号、分段、方式和前序任务；JSON 报告包含 `shipments` 和 `consignment_totals`。

## 数据性质与来源

地点使用近似 WGS84 地理参考；省界来自 [DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)。港口名称和地理位置参考 [台湾港群](https://www.twport.com.tw/zh-tw/business/Guide?a=110)、[台中港地理位置](https://tc.twport.com.tw/about/Articles?a=758)及[高雄港总图](https://kh.twport.com.tw/zh-TW/about/Articles?a=901)。

连线是教学仿真的运输走廊，陆运距离采用大圆距离 ×1.22、海运距离采用 ×1.12；不是实测道路或航道，也不表示当前实际开通的具体航线、班期或通行许可。海上中继点明确标为“模拟”。

## 验证

后端 `test_regional_transport.py` 覆盖运力与通道匹配、接驳依赖、实际延误传播、上游失败取消、地面路径不能跨海、缺少船舶时不生成后段、API 衔接校验和整票重量去重。前端 `test_shipments.mjs` 覆盖接驳期间状态、失败/未分配状态及整票路径排除空驶与其他运单。
