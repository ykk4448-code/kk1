# 中国地理底图与悬浮工作台

地图现在是全站唯一的底层画布：`map-stage` 覆盖整个视口，业务面板、导航、表单与回放器在其上方。基础数据、想定、规划、推演和评估使用同一地图组件，避免在卡片中反复创建地图。

## 底图和交互

- 首页展示中国全图及五个业务入口；工作台进入当前选择的全国运输或城市场景。
- 全国跨区域物流默认显示省级政区图，城市场景默认显示 OpenStreetMap 街道底图，提供“政区图 / 街道图”切换。省级和城市区县矢量边界随项目一起提供，街道瓦片不可达时仍有可用地理底图。
- “中国”返回全国省界视图；全国视图可点击武汉、上海、成都、深圳进入对应场景。“⌖”适配当前任务或全部设施。
- 支持拖动、滚轮缩放、缩放按钮；聚焦地图后，方向键平移、Home 查看全国。所有坐标通过相同的 Web Mercator 投影对齐。
- 任务路线采用平台配色，共用通道错开显示；可选择全部任务、选中平台、选中任务。任务选择、平台位置、阶段、事件和回放时间保持联动。

## 布局

桌面评估与推演控制页采用顶部导航、一行场景/运行/城市选择、一行指标和大面积地图。默认保留左侧任务时序与底部播放条；详情、统计、事件、平台、路线图例、时间快捷定位均按需展开。任务列表也可单独收起。选择任务时自动打开右侧详情，并展示取货、运输、交付阶段；事件和平台共用该区域，避免同时堆叠。统计曲线在地图下部独立展开。新建多轮推演是单行入口，展开后再填写参数。

其他业务模块采用左侧可滚动工作面板，指标压缩为一行，表格在面板中横向滚动，“展开面板”适合编辑和对比。想定页面先展示当前场景，按需展开场景目录；规划页面将甘特图和任务明细放在可展开区域。桌面顶部保留本模块二级功能。手机和平板采用地图、任务、详情、统计、事件、平台标签切换底部面板，默认优先显示地图；其他模块使用底部或侧面工作面板和二级标签。布局覆盖样式依次为 `map-workspace.css` 与 `map-comfort.css`。

## 历史数据与地理场景

新增 `nodes.network_id` 和 `scenarios.network_id`，默认 `baseline`，数据库迁移仅追加字段。历史节点和旧方案快照不会被覆盖。

旧数据库若只有重复经纬度的相对坐标节点，会新增独立的 `SCN-GEO-WH` 武汉地理场景：32 个设施、79 条合成通道、16 台平台、24 个任务及三种策略的规划和推演。其设施采用近似地标坐标，路段和任务为仿真数据。原场景继续使用原路网；历史 XY 快照显示在注明“无地理定位”的独立拓扑框内，不把相对坐标伪装成真实地理位置。

按场景路网过滤节点、通道、平台、规划和编组；后端拒绝跨路网端点。新安装原本已有独立经纬度时，直接使用已有地理路网，不重复新增迁移场景。用户新建设施和想定沿用当前路网。

首次进入当前版本时默认打开“全国跨区域物流”；之后记住用户自行选择的范围。武汉地理演示和历史场景始终保留在选择器中。全国陆海联运的数据和接驳机制见 [全国跨区域运输说明](regional-transport.md)。

## 数据来源

行政区划数据来自 [阿里云 DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)，上游注明来自高德；[官方使用说明](https://help.aliyun.com/zh/datav/datav-7-0/user-guide/datav-geoatlas-widgets/)将其定位为学习交流数据。本项目为教学仿真演示，保留来源标注。

固定数据地址为 `https://geo.datav.aliyun.com/areas_v3/bound/{adcode}_full.json`，全国 `100000`，武汉 `420100`、上海 `310000`、成都 `510100`、深圳 `440300`。全国数据包括大陆省区市、台湾、香港、澳门和南海相关要素，共 35 个要素；四座城市分别有 13、16、20、9 个区县要素。数据下载于 2026-10-20，经 GCJ-02 到 WGS84 迭代反算后固化到 `map-data.js`，保留六位小数。转换用于演示地图对齐，不代表测绘精度。

街道瓦片使用 `https://tile.openstreetmap.org/{z}/{x}/{y}.png`，页面保留 [OpenStreetMap 贡献者署名](https://www.openstreetmap.org/copyright)。仅按当前交互视口请求，不提供批量下载或离线街道缓存；遵循 [瓦片使用政策](https://operations.osmfoundation.org/policies/tiles/)。

原始数据 SHA-256 和地址记录在 `docs/map-data-sources.json` 及地图模块中。需要更新边界时，可运行 `python scripts/update_map_data.py` 重新下载、转换并生成资源，再运行地图数据测试。
